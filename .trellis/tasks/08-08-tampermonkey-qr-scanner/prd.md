# Tampermonkey QR code scanner

## Goal

在任意普通网页中快速识别二维码，减少用户下载图片或切换设备的步骤。脚本应提供一个轻量入口，让用户扫描当前网页可见内容，或像截图工具一样框选网页区域后识别二维码。

## Confirmed Facts

- 当前仓库只有 Trellis 脚手架，没有现有前端代码、构建配置或测试。
- 交付物是可安装到 Tampermonkey 的 userscript；不依赖后端服务。
- 识别结果需要在页面上反馈给用户。
- 当结果是网页地址时，用户应能直接打开该地址。

## Requirements

### R1. Script installation and page safety

- 提供标准 Tampermonkey 元数据，能在普通 HTTP(S) 网页运行。
- 不破坏宿主页面的布局、事件和原有交互；脚本 UI 使用隔离的容器和明确的 z-index。
- 默认不向第三方上传网页截图或二维码内容。
- 不在网页中常驻浮动按钮；通过 Tampermonkey 菜单命令 `QR Scanner` 打开面板。

### R2. Scan current page

- 用户可从脚本入口触发“扫描当前网页”。
- 脚本捕获当前页面可见区域，调用二维码解码器识别首个可识别的二维码。
- 识别成功时展示原始文本，并区分 URL 与普通文本。

### R3. Select and scan region

- 用户可进入框选模式，在页面上拖拽选择矩形区域。
- 框选层能显示选择范围，支持取消；选择完成后只对该区域进行识别。
- 空选择、跨 iframe 或无法读取的内容应给出可理解的失败反馈，不得让页面卡死。

### R4. Result interaction

- 结果面板支持复制原始内容。
- URL 结果提供打开动作；打开动作遵循浏览器安全策略，并明确是否新开标签页。
- 公众号 `weixin.qq.com/r/...` 扫码关注链接不得伪装成普通网页：显示客户端限制说明，并提供最佳尝试的微信唤起动作。
- 官方 `weixin://dl/business/...` 小程序 Scheme 可交给微信客户端；其它未知自定义 Scheme 不执行。
- 无结果、识别中、成功和异常状态均有可见反馈。

### R5. Compatibility and performance

- 支持 Chromium 系 Tampermonkey 的现代网页；不使用 `getDisplayMedia`，避免每次扫描触发标签页共享授权。
- 逐张读取可见图片、Canvas、SVG 的原始分辨率；跨域图片通过 Tampermonkey 资源请求能力读取，不执行会阻塞页面的整页 DOM 截图。
- 识别操作应可取消，避免长时间阻塞主线程；脚本资源应适合直接安装和离线使用。

## Acceptance Criteria

- [ ] 安装脚本后，在 HTTP(S) 网页上能打开扫描入口且页面原有内容仍可操作。
- [ ] 对包含二维码的当前页面执行扫描，能展示正确的原始文本；URL 结果有可用的打开按钮。
- [ ] 框选包含二维码的区域后能正确识别；取消框选不会改变页面内容。
- [ ] 对无二维码区域、空选区和解码异常显示明确状态，且页面不会卡死。
- [ ] 结果可复制；脚本不会把截图或结果发送到远端服务。
- [ ] 在至少一个 Chromium 浏览器桌面视口和一个窄视口完成手工验证，并记录验证命令/步骤。

## Resolved Scope Decisions

- 二维码解码器随脚本打包，安装后离线可用，不使用运行时 CDN；接受脚本体积更大，以换取隐私和可预测性。
- 插件只通过 Tampermonkey 菜单命令打开，不在页面常驻按钮。
- 扫描只读取可见 `img`、`canvas` 和 `svg` 的原始像素；跨域图片通过 Tampermonkey 请求能力读取，因此扫描时不再请求标签页画面共享，也不执行整页 DOM 渲染。

## Out of Scope

- 不做服务器端 OCR、登录、历史记录同步或二维码生成。
- 不承诺读取浏览器标签页之外的系统级屏幕；本任务只覆盖当前网页及用户框选的网页区域。
