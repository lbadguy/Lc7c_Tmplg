# Tampermonkey QR Scanner

离线 userscript，可扫描当前网页可见区域，或拖拽框选网页区域识别二维码。二维码内容只在本地处理，不上传截图或结果。

## 安装与构建

```powershell
npm install
npm run build
```

将 `dist/qr-scanner.user.js` 导入 Tampermonkey。脚本仅匹配 `http://` 和 `https://` 页面，不在网页中常驻按钮。使用时点击 Tampermonkey 图标，再点击脚本菜单中的 `QR Scanner`。

在 `linux.do` 页面打开 Tampermonkey 菜单，可切换“Linux.do 帖子新标签页”。默认关闭；开启后，普通左键点击话题列表中的帖子标题会在前台新标签页打开。Ctrl/Shift/Alt/Command 点击、中键点击和帖子内跳转保持浏览器原有行为，设置会保存在 Tampermonkey 脚本存储中。

## 权限说明

脚本声明了两项 Tampermonkey 权限，装机时会提示：

- `GM_registerMenuCommand`：在 Tampermonkey 菜单里注册 `QR Scanner` 和 `Base64` 两个入口，避免在页面上常驻悬浮按钮。
- `GM_xmlhttpRequest` 配合 `@connect *`：只用于一件事——当页面里的图片来自其他域名时，浏览器会污染画布导致无法读取像素，此时脚本按图片自身的 URL 重新取一次原图。

`@connect *` 的范围确实宽，因为二维码图片可能来自任意 CDN，无法预先列举域名。脚本只会请求页面中已经存在的图片地址，不会主动访问其他 URL，也不会把截图或识别结果发往任何服务器。所有解码都在本地完成。

更新脚本后如果旧的“新建用户脚本”仍显示右下角按钮，请在 Tampermonkey 的“已安装脚本”中停用旧脚本，只保留 `QR Scanner (offline)`。新版本可能在安装时请求一次跨域图片读取权限，这是为了读取页面已经展示的图片，不是标签页共享权限。

扫描结果可复制。普通 `http:` / `https:` 地址显示“新标签打开”；公众号 `weixin.qq.com/r/...` 链接显示“尝试唤起微信”并解释浏览器限制；官方微信小程序 Scheme 显示“在微信打开”。框选使用指针拖拽，空选区可取消并会显示提示。

面板中的“系统文字识别”按钮会调用 Windows 的 `ms-screenclip:` 系统协议，打开系统截图工具的选区界面。它不是网页截图，也不是伪造 `PrtSc` 按键；完成选区后可在 Windows 截图工具中使用“文本操作”。如果浏览器拦截外部协议，请使用 `Win+Shift+S`，或在 Windows 中确认已安装截图工具。

## 识别流程

脚本读取页面中可见图片、Canvas 和 SVG 的原始像素，**先按框选区域裁剪**，再逐个候选解码，命中即停止。

裁剪是准确率的关键。一张 3000×2000 的截图里的二维码，如果整张送进解码器，二维码本身可能只占很小比例而无法定位；裁剪到框选区域后，同一个码在几十毫秒内就能解出。所以框选比“扫描当前页”更准也更快。

解码依次尝试：浏览器原生 `BarcodeDetector`（Chrome / Edge 支持，Firefox 和 Safari 目前没有）、jsQR、以及把过小的区域整数放大后重试。深色背景上的浅色二维码也能识别。

单次扫描有约 2.5 秒的时间预算。超时会提示缩小框选范围，而不是谎报“未发现二维码”。由于 jsQR 是同步执行、开始后无法中断，实际最长可能到 3 秒左右。

失败原因会区分：区域里没有可读取的图片、读到了图片但像素受跨域限制、以及确实读到像素但其中没有二维码。

## 已知限制

- 纯 CSS 背景图和仅存在于跨域 iframe 内部的二维码无法读取。
- 图片使用 `object-fit: cover` / `contain` 等非默认值时，显示尺寸与原始像素不成比例，按比例换算会裁错位置。这种情况下脚本放弃裁剪、改为解码整张图，因此一张图里有多个二维码时，可能解出的不是你框选的那个。
- 一次只返回一个识别结果。
- 脚本不会上传截图或二维码结果，所有处理都在本地完成。
